**Ensure JSON uses empty slices (not null) and surface per-file write failures**
Two related issues in `initWorkspace`:
1. **Nil vs empty slices in JSON**
   `created`, `skipped`, and `errors` all start as `var []string`. If no entries are added, they remain `nil` and will serialize as `null`, which conflicts with the guideline to return empty slices/maps in JSON responses.
   Initialize them explicitly to empty slices:
   ```diff
-	var created []string
-	var skipped []string
-	var errors []string
+	created := make([]string, 0, len(agents))
+	skipped := make([]string, 0, len(agents))
+	errors := []string{}
   ```
2. **Errors are reported in the payload but never cause a non-zero exit**
   When `os.WriteFile` fails, you append to `errors` but still return `nil` error from `initWorkspace`. From a CLI/automation perspective, that means `agentctl workspace init` can partially fail while still exiting 0.
   Consider treating any non-empty `errors` as a failure condition and returning an error alongside the detailed payload, e.g.:
   ```diff
-	result := map[string]any{
+	result := map[string]any{
 		"workspace":    workspaceDir,
@@
-		"summary": fmt.Sprintf("Created %d agents, skipped %d, errors %d",
-			len(created), len(skipped), len(errors)),
+		"summary": fmt.Sprintf("Created %d agents, skipped %d, errors %d",
+			len(created), len(skipped), len(errors)),
 	}
-
-	return result, nil
+	if len(errors) > 0 {
+		return result, fmt.Errorf("one or more agent files failed to write")
+	}
+	return result, nil
   ```
   The envelope body will still expose detailed per-file error messages, but callers also get a clear signal via the return error / exit code.
